# 测试说明

## 仓库测试

```bash
mvn clean verify
```

仓库自带测试验证 Spring Boot 自动配置、客户端复用、监听器签名、看板认证、只读查询、分页参数、错误处理和资源加载。Redis 客户端在这些测试中使用隔离的桩对象，不代表真实 Redis 故障或并发验收。

## Redis 集成验证

在受控测试环境使用真实 `RedissonClient`，为每轮测试创建独立随机命名空间。结束时按已知完整键名清理，不扫描真实业务键或清空数据库。测试连接由验证方注入，不在仓库保存地址、账号、口令或完整环境配置。

建议覆盖：

1. 到期前不可领取，正常确认后结束；发送重试和完成后重试保持幂等。
2. 多消费者竞争时同一时刻只有一个有效领取凭证。
3. 未确认消息在处理权到期后恢复，旧凭证不能确认、重试、拒绝或续期。
4. 失败按配置退避，到达上限后进入死信；支持重放和删除。
5. 待执行消息可取消或改期，处理中消息不能被这些操作撤销。
6. 自动续期、最长执行时间、正常停机和异常退出的恢复行为。
7. 队列容量、消息大小、命名空间隔离、错误键类型和去重窗口。
8. 目录跨客户端可见，监控读取不改变消息或处理权。
9. 看板匿名访问拒绝、正文按需加载、凭证隐藏及应用原有认证隔离。

持久化、主从切换、Redis Cluster、网络分区、时钟变化和压力验证依赖实际部署拓扑，应单独执行。小样本到期延迟不能代替任意负载下的实时保证。

## 发布前检查

使用 `mvn clean install` 重新生成构件，核对三个组件 JAR 中的 `META-INF/LICENSE`、`META-INF/NOTICE`、Lua 和看板资源。开源源码包不包含 `.git`、`target`、日志、本机配置或连接凭据。
