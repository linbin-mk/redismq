# MySQL 历史分析验收 — 2026-11-09

> 本报告记录当时版本的验收结果。后续已移除看板内置 Basic 认证及 Spring Security 依赖，当前安全策略由接入项目负责，详见 [README](../../README.md)。

本轮实现可选 `redis-mq-dashboard-mysql` 扩展：队列趋势、分钟级处理指标、独立小连接池、可配置滚动保留期及自动分批回收。默认保留 5 天，允许分析统计出现缺口，不保存消息正文或逐条消费历史。以下数据记录发布前 `0.3.0-SNAPSHOT` 的功能实施验收；正式发布版本及变更以 [CHANGELOG](../../CHANGELOG.md) 和对应 tag 为准。

发布阶段另外修复了测试夹具的空库初始化顺序：每个 MySQL 集成用例先显式准备分析表，故障隔离用例可以独立在零表数据库中首先运行，不依赖其他测试类。产品仍不自动建表。

## 功能与边界

- 真实 HTTP 认证、只读历史查询、队列名及时间参数校验、未启用时的降级行为。
- 真实消息发送、重试、死信、确认、业务回调结果及领取/处理耗时进入 MySQL；多个实例计数合并，单采集者租约与接管。
- 累计指标重复写入和迟到写入不重复累加；旧租约不能覆盖新快照；队列名区分大小写，监控源与 namespace 隔离。
- 过期记录立即从查询排除，后台按监控源分批清理；重复清理安全，不影响其他监控源。Redis 采样不可用时仍执行 MySQL 回收。
- 真实插入 100001 条指标，验证覆盖索引扫描预算拒绝超大历史查询；返回点数始终不超过请求上限。
- 无界队列名、长时间数据库故障均不能突破聚合窗口容量；配置启动时冻结；不同实例配置冲突时降级。
- 借用宿主数据源不接管或关闭连接池，恢复连接状态，兼容默认关闭自动提交的连接。关闭采集器后，迟到 RPC 不会把 STOPPED 状态改回运行状态。
- Redis maxmemory 拒绝新增正文后，原消息去重、继续领取与确认可用，消息数量和正文容量记账正确。短防重别名可能因即时内存余量而成功或被拒绝，不能由此创建第二条消息。

## MySQL 实际停机与恢复

使用测试专用宿主和 `scripts/history-e2e.py` 实际停止、启动本轮 MySQL 容器，未使用模拟数据库异常替代：

| 阶段 | 发送接受累计 | 业务完成累计 |
|---|---:|---:|
| 停库前 | 311 | 293 |
| 停库期间 | 343 | 322 |
| 恢复后 | 380 | 358 |

停库期间继续接受 32 条、完成 29 次业务处理；历史查询返回 503。恢复后状态回到 RUNNING，持久化确认计数从 114 增至 179，丢弃统计事件为 0。查询裁剪到最近 5 天，请求 17 点返回 17 点。原始记录见 [mysql-outage-e2e.json](mysql-outage-e2e.json)。

测试流量包含预设的拒绝与重试，成功数与接受数不要求相同。宿主的过去 72 分钟展示数据是明确标识的合成数据；停库、恢复、实时消息流转与 HTTP 返回均为真实操作，历史展示数据不能用于吞吐测量。

## 性能实测与范围

开启 MySQL 分析的 4000 条、1 KiB、8 个生产者/8 个消费槽负载，Redis 7.4 用时 4.651 秒，约 860.0 条/秒；Redis 6.2 用时 4.900 秒，约 816.3 条/秒。均完成全部消息，最终计数入库，统计丢弃为 0。它们是受限本机容器中的完整流程测量，不是生产容量上限，也不是监控开关的严格 A/B 开销比较。

统计回调只累计有界内存，不同步等待 SQL，也不新增 Redis 监控写入。快照查询复用有界队列统计接口；历史查询只读取 MySQL。默认最多两个独立连接，单个历史查询并发，SQL 1 秒、连接 1 秒、socket 2 秒超时；故障退避与内存过期丢弃不进入 MQ 就绪检查。

没有将本轮结果记为“零慢查询”：采集的 Redis 7.4 最近 128 条慢日志（阈值 1 ms）最高 9.818 ms；Redis 6.2 有 3 条慢日志（阈值 10 ms），最高 20.616 ms。两个实例 evicted_keys、rejected_connections 均为 0，没有发生挂死。记录来自多轮回归的累计近期日志，不能归因于某一次请求或视为完整耗时分布，详见[运行摘要](redis-runtime.json)。生产环境仍需结合实际队列数、共享资源和部署拓扑验证容量；本轮没有测试 Redis Cluster、复制故障切换或跨机网络分区。

## 构件、文档与清理

四个模块的主 JAR、sources JAR 和 javadoc JAR 均生成。核对 Java 17 字节码、LICENSE/NOTICE、Lua/JS/SQL 与源码一致，发布 JAR 不含测试宿主或夹具，见[构件检查](artifacts.json)。README 中英文、CHANGELOG、CI 测试矩阵和[接入指南](../MySQL历史分析.md)已更新；`git diff --check` 通过。

上线接入前需显式执行 V1 SQL，并配置稳定的 source-id 与专用 MySQL 连接；运行时不自动建表。自动回收需要至少一个该监控源实例运行，永久停用或更换 source-id 时需交接旧范围清理。历史分析的保留与清理不删除 Redis 中的业务消息。

本轮临时宿主与五个专用 Docker 容器已回收，临时数据库凭据文件已删除；已有其他 Docker 容器保持运行。
